# Свайп в модалках `TesseraPopup`: QA на устройстве (Chunk 3a)

> Разделы до «Перепроверка Chunk 1.2» описывают код 1.1 (`TesseraPopup.kt` от 18:35, APK 19:04). Код 1.2 (фокус снимается после ухода) — в разделе «Перепроверка Chunk 1.2» в конце.

**Устройство:** `emulator-5556` (AVD `Small_Phone`), API 36, 720×1280 px, 320 dpi, 1 dp = 2 px. Gesture navigation.

**Код:** ветка `feature/editor-header-and-popup-gestures`, база `7ec94b4`. Сверху незакоммиченный Chunk 1 (`TesseraPopup.kt`) вместе с правками ревью роли ui (Chunk 1.1, файл от 18:35): флаг `gone` без анимации выхода, цель ухода `max(windowHeight, goneAtPx + cardHeight)`, проверки `currentVisible`, Back во время ухода поглощается.

Первый проход на устройстве (APK от 18:17, код до правок ревью) дал те же выводы. Все записи и числа ниже — второй проход: APK от 19:04 с текущим `TesseraPopup.kt`. Instrumented-класс тоже перепрогнан на текущем коде. `TesseraPopup.kt` с 18:35 не менялся: сверено по mtime перед финальными прогонами. Редактор (Chunk 2) в этом APK — промежуточное состояние роли feature; для модалок это неважно.

**Клавиатура:** Gboard. На время прогона включены `show_ime_with_hard_keyboard 1` и `stylus_handwriting_enabled 0`. После прогона возвращено: `0` и `settings delete` (до правки было `null`).

**Данные:** временный сидер в androidTest. Он создал 18 папок (одна вложенная), 30 тегов и 11 заметок, после запуска удалён из дерева. Цель — чтобы контент прокручивался в каждой модалке, где это возможно.

**Сырьё** лежит в `.claude/local/editor-header-and-popup-gestures-ref/qa/`:
- `NN-<модалка>-<сценарий>.mp4` — запись экрана;
- `NN-…/NNN.png` — все кадры записи (360×640, половина экрана), `pts.txt` — их время;
- `NN-…-sheet.png` — контактный лист с номером кадра и мс;
- `pass1-*-release*.png` — увеличенные кадры вокруг отпускания из первого прохода, на коде до правок ревью. На них видна перестройка Gboard в момент снятия фокуса (наблюдение 1);
- `main-TEST.xml` — JUnit XML финального прогона, `popup-regression-TEST.xml` — `TesseraPopupTest`, `base-probe-*` — прогон тех же тестов против базового попапа.

**Как читать кадры.** Скрипт находит в каждом кадре верх карточки. Признак карточки — тёплый цвет поверхности (R − B ≥ 11) в столбце x = 338 у правого края карточки. Ещё он меряет яркость фона на левом поле (x = 5, y = 300), куда карточка не заходит. Числа ниже даны в px кадра (половина экрана): верх карточки / яркость фона. «—» значит, что карточки в кадре нет. Запись эмулятора идёт с частотой 20–35 кадров/с, поэтому одиночный кадр в 16 мс она может пропустить. Главный покадровый судья — instrumented-тест.

- (*) 100 dp за 300 мс ниже порога и по расстоянию, и по номиналу скорости, но закрыл.
- (**) 130 dp за 800 мс номинально за порогом, но не закрыл.

Номинал `adb input swipe` на нагруженном эмуляторе не равен скорости, которую видит `VelocityTracker`: события приходят пачками, последний отрезок бывает быстрее или медленнее среднего. Значит, одиночные результаты (*) и (**) — шум подачи. На поведение кода это не указывает. Устойчиво видно следующее:
- тапы, дрожание и медленные оттягивания не закрывают никогда;
- уверенный короткий взмах закрывает всегда, даже 20–40 dp;
- пограничная зона — 400–530 dp/с при 60–80 dp.

**Предложение:** оставить 120 dp и 500 dp/с. Ложных закрытий нет, короткий уверенный взмах закрывает. Пересмотреть стоит только по жалобе на реальном телефоне, что «умеренный» свайп (~60 dp за 150 мс) не закрывает. Тогда — 400 dp/с: это всё ещё вдвое выше дрожания и медленного «посмотреть и отпустить» (75–160 dp/с).

   - Если захотите, чтобы хватало одного тапа: `TesseraPopup` должен сообщать наружу, что карточка уходит. Решение за оркестратором.

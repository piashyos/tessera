# Нативный редактор, этап 2 — QA картинок на устройстве (P2-3a)

Устройство `emulator-5556`: AVD `Small_Phone`, API 36, 720×1280, 320 dpi, `font_scale` 1.0, тема системы светлая, Gboard. Ширина
текста в приложении — 640 px (экран минус 2 × 20dp), в тестовом `DeviceEditor` — 704 px. HEAD `111d501` (в нём `c3e9805`: правки картинок
по ревью и таблицы). Ветка `feature/native-editor`.

Классы — `app/src/androidTest/java/app/tessera/ui/editor/`:
- `screen/NativeImageSizeTest`, `screen/NativeImageEditTest`, `screen/NativeImageOpenCloseTest`, `screen/NativeImageGalleryTest`;
- `screen/NativeImageShotsTest` — скрины для сверки вида;
- `engine/NativeImagePerfTest` — перф, запускается отдельным процессом;
- общий код — `screen/ImageFixtures.kt`.

Фикстуры — настоящие WebP-файлы. Их пишет тот же формат, что `ImageCompressor` (lossy, 80), в папки приложения
(`filesDir/images` со строкой Room без Drive-id или `cacheDir/images`). Drive-фейк подложен на уровне `NoteImageDecoder` + `NoteObjectImageSource`
поверх `DeviceEditor`. Чтобы снять кадры до прихода картинки, декод держится защёлкой на `NoteImageDecoder.fileDecoder`.

Скрины и склейки «нативный | Aztec» — `.claude/local/native-editor-ref/qa/p2/` (`stitch-{a,b,c}-{light,dark}.png`, исходники в `shots/`,
пересборка — `stitch.sh`). Логи прогонов — `qa/p2/logs/`.

## Перепроверка после фикса декодера (78a9868) и правок ревью (01deaac)

- `NativeImageSizeTest` — 7/7 зелёный на 78a9868: Н1, Н2, Н3 исправлены. Размер до декода = после для всех 11 файлов × 3 ширины,
  повёрнутые фото во всю ширину по формуле §3.1, файл без хвоста → «недоступно» и лечится с Drive.
- Новый тест `colorsAndAlphaAreWhatBitmapFactoryGave` (78a9868 перешёл на `ImageDecoder` на API 28+): lossy-фото 1001×563 и lossless с
  прозрачностью 400×300 — разница с `BitmapFactory` по цвету 0, по альфе 0; `ARGB_8888`, `hasAlpha` совпадает. Скрины `NativeImageShotsTest`
  на 01deaac против 111d501 (`qa/p2/shots-111d501/`, без строки состояния): 0 отличающихся пикселей во всех кадрах, кроме «выделенной
  картинки» — там пропали розовые полосы Н4.
- Пик памяти (`NativeImagePerfTest#aPhotoDecodesWithNoMoreMemoryThanBitmapFactoryTook`): декод фото 2048×1536 на 704 px — медиана пика
  native heap 4,7 МБ у `ImageDecoder` и 4,7 МБ у прежнего `BitmapFactory`, время 13,2 против 13,0 мс (7 прогонов вперемешку). Не вырос.
- Перф на 78a9868: открытие 20 картинок — медиана 39,0 мс (prefetch 19,0 + layout 16,0), все 20 картинок — 251,6 мс, высота layout не
  меняется, native heap 17,2 → 49,2 МБ после 5 открытий и скролла. Клавиша: 3,5 мс с картинками против 1,5 мс без них. Проверка теста
  теперь — критерий плана «не медленнее этапа 1» (30,5 мс, план этапа 1); оба числа в логе. Н6 остаётся как наблюдение (≈ 2 мс сверху).
- Н4 попиксельно (`NativeImageHighlightTest`, 01deaac): тап по картинке — в полосах над и под рамкой 0 изменённых пикселей; выделенное слово
  подсвечено (2466 из 3696 px его прямоугольника). Н4 исправлена.

## Перф

`NativeImagePerfTest` идёт отдельным процессом, без `uiAutomation`. Заметка — 20 фото 2048×1536 (так их хранит компрессор) на ширину
экрана, 704×528 после декода, и 21 абзац текста. Каждый прогон — холодный декодер: новый процесс не знает размеров. Prefetch — то, что
делает ViewModel до выдачи content: `NoteMarkdown.parse` + `prefetchSizes`, на каждую картинку строка Room и границы файла, на IO. Логи —
`qa/p2/logs/perf-111d501.log`, `perf2-111d501.log` (второй прогон, честный порядок клавиш).

| Замер | Медиана, 5 прогонов (2-й прогон) | Значения |
| --- | --- | --- |
| prefetch | 31,6 мс | 32,5 · 31,9 · 31,6 · 15,7 · 18,2 |
| `setMarkdown` → первый layout | 17,2 мс | 35,3 · 17,2 · 18,7 · 15,4 · 11,8 |
| **открытие: prefetch + первый layout** | **52,8 мс** (≤ 300 ✓; 1-й прогон — 55,1) | 71,7 · 52,8 · 54,0 · 32,9 · 32,5 |
| до первого кадра | 55,0 мс | |
| пока не пришли все 20 картинок | 170,5 мс | 229 · 146 · 255 · 146 · 171 |
| высота layout до и после прихода картинок | 13022 → 13022 во всех прогонах | прыжка нет |

База этапа 1 на том же устройстве и в том же процессе (`NativeEditorPerfTest`, 1000 абзацев): первый layout — медиана 101,9 мс (в плане —
144 мс), ключ первым в серии — 35,1 мс, внутри серии — 12,9 мс.

Память (`Debug.getNativeHeapAllocatedSize`, Java после GC):
- до — native 17,2 МБ, Java 3,5 МБ из 201;
- после 5 открытий, последняя заметка на экране — 49,1 МБ / 3,6 МБ;
- после скролла через все 20 картинок туда и обратно — 49,2 МБ / 3,6 МБ.

Прирост +32 МБ — ровно 20 битмапов 704×528×4. Кэши прошлых открытий освобождаются, OOM нет.

Скролл программный, шаг 120 px, кадр 16 мс:
- с картинками — 197 кадров, медиана 17,5 мс, > 33 мс: 24 (12 %), max 50,3 мс;
- тот же текст без картинок — 18 кадров, медиана 18,5 мс, > 33 мс: 1, max 33,7 мс.

На эмуляторе все кадры длиннее 16,7 мс, и с картинками, и без. Вывод о рывках на эмуляторе не делается.

Клавиша (первая в серии, `commitText`, 20 раз). Сначала тот же текст без картинок, потом с ними — чтобы прогрев не играл за картинки:
- без картинок — медиана 5,1 мс;
- с 20 картинками — медиана 11,5 мс, max 14,9 мс.

Критерий плана «не медленнее этапа 1» выполнен: 11,5 мс против 35,1 мс у этапа 1, меньше кадра. Более строгая проверка теста (с картинками не
медленнее того же текста без них больше чем на 2 мс) красная — Н6.

## Не проверено

- Настоящая загрузка с Drive в приложении: нужен вход. Самовосстановление проверено на уровне декодера и редактора с фейком Drive.
- Живой Gboard со стикером или GIF через его UI. Проверен тот же вызов `InputConnection.commitContent` с тем же
  `INPUT_CONTENT_GRANT_READ_URI_PERMISSION`, и поле объявляет `image/*`.
- Старая сборка (до `c3e9805` / до фикса prefetch): Back во время prefetch на ней не гонялся, проверено только, что сейчас заметка цела.
- Другие размеры, плотности, `font_scale` 1.3, поворот устройства — только 720×1280 @ 320 dpi.
- Выделение картинки в Aztec — для сравнения не снималось.
- Зритель — только через отдельный `NoteBody(editable = false)`, не через экран редактора с `isReadOnly` (нужен вошедший зритель общей заметки).
- `bringPointIntoView` при догрузке проверен на `DeviceEditor` (тот же `TesseraEditText`), без `NoteBody` / `TableOverlayHost` в приложении.
- Перф прокрутки на эмуляторе не показателен: все кадры > 16,7 мс и без картинок.

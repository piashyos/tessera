# Живой фон (градиент от касаний, размер зерна) — QA жестов на устройстве (Chunk 4)

**Устройство.** `emulator-5556`: AVD `Small_Phone`, API 36, 720×1280, 320 dpi. Рендер — SwiftShader, то есть GPU эмулирован на CPU хоста. `wm size` и `wm density` не менялись.

**Настройки устройства.**
- `animator_duration_scale` = **1** (проверено в начале; каждый тест `BackgroundGradientTest` проверяет его ещё раз).
- Клавиатура — Gboard. На время прогонов `show_ime_with_hard_keyboard 1` и `stylus_handwriting_enabled 0`, в конце возвращены.

**Код.** Ветка `feature/animated-background`: база `7ec94b4` плюс незакоммиченные Chunk 1–3. Прод-код менялся во время QA:
- 12:26 — `try/finally`: снятие слушателя посреди жеста работает как отмена;
- 13:56 — «импульс» на каждое первое нажатие вместо «вдоха» на тап (спека §4.1–§4.2).

У каждого прогона ниже указано, на каком коде он собран.

**Как тесты трогают экран** — как в `AppearanceAppTest`: без Compose-правила, на реальных часах приложения.
- Касания — `MotionEvent`, инжектированные в окно через `UiAutomation`.
- Клавиши — тапы по клавишам Gboard через `input tap`; клавиши найдены по accessibility-узлам окна клавиатуры.
- Пиксели — `UiAutomation.takeScreenshot()` всего экрана.

**Какие классы проходят через `GrainOverlay`.** Только те, что запускают `MainActivity`; только у них работает слушатель фона:
- `AppearanceAppTest` и наследники: `TagFolderAppearance*`, `BackgroundGradient*`;
- `NativeAppTest` и наследники: 27 из 28 классов `ui.editor.screen`.

Не проходят: `NotesListScreenTest`, `TesseraSwipeableNoteCardTest`, `TesseraPopupSwipeTest`, `NativeEditorReadOnlyShotTest` — у них свой `setContent` без фона. Поэтому свайп карточки, скролл списка и тап по заметке в настоящем приложении с градиентом проверяет новый `BackgroundGradientTest.withTheGradientOnTheListScrolls…`.

**Сырьё** — `.claude/local/animated-background-ref/qa/`:
- `runs/` — вывод Gradle по прогонам и скрипты: `junit_cases.py` (разбивка по классам из JUnit XML), `perf.sh`, `cmp.py`, `ampdiff.py`;
- `test/`, `shots/`, `pulse/` — кадры;
- `perf/` — сырые `dumpsys gfxinfo`.

### `NativeTableImeTest.typingInACellTakesAutocorrectionAndBackspace` — не градиент

Выключатель градиента для одного класса добавлен в `NativeAppTest`: аргумент `-e gradient off`, без аргумента ничего не меняется. С градиентом и без — одна и та же картина, 4 прогона из 4 (`logcat -s NativeTableIme`):

```
the same keys " teh zx" + Delete: in the text -> "after the table teh z " (suggestions []); in the cell -> "red teh z" (suggestions []); cells on screen [Fruit, Note, apple, red teh z ]
```

- У Gboard пустая строка подсказок, и «teh» не исправлен ни в тексте, ни в ячейке. Поэтому первая проверка теста («ячейка как текст») проходит.
- Падает вторая: на экране ячейка `red teh z ` с пробелом в конце, а в Markdown — `red teh z`.
- Автозамена — настройка и состояние клавиатуры устройства, градиент на неё не влияет.

Вывод: нестабильность окружения (Gboard на `emulator-5556`), не фича. Почему у Gboard пропали подсказки, не выяснял. В 12:18 я один раз делал `am force-stop` Gboard, чтобы вернуть полную клавиатуру вместо узкой панели. Подсказки после этого в ручной проверке были (`probe/editor-ime5.png`), но связь не исключаю.

## `BackgroundGradientTest` — что и как сравнивается

**Фикстура.** Пустой список: полоса между верхней панелью и текстом «No notes yet», `Rect(32, 200 – 688, 631)` — 282 736 px. Для редактора — полоса между последней строкой и панелью формата при поднятой клавиатуре, `Rect(32, 400 – 688, 522)`.

**Покой.** Кадр покоя — второй из двух кадров с интервалом 400 мс, совпавших до пикселя. Шум «покой против покоя» — 0 px во всех прогонах: зерно статично, в покое ничего не анимируется.

**Порог.**
- «Изменился» — пиксель, у которого отличается хоть один канал.
- «Двинулся» — изменилось ≥ 5 % полосы. Замеры: удержанное перетаскивание 89.7 % (light) / 92.7 % (dark) / 71.4 % (редактор), импульс тапа через 400 мс — 71.0 %. 5 % — в 14 раз меньше самого малого замера, при шуме 0.
- «Вернулось» — 0 изменённых пикселей: пружины заканчиваются точно в покое.

| --- | --- | --- |

## Плавность

**Метод.**
- `GradientPerfFixture` — ручной «тест», в обычных прогонах пропускается через `assumeTrue`. Запуск: `am instrument -e perfGradient on|off`. Кладёт 30 заметок (light, WARM, зерно по умолчанию) и включает или выключает градиент.
- Дальше `am force-stop`, `am start` — приложение без инструментации и без accessibility-клиента.
- `dumpsys gfxinfo app.tessera reset`, 5 свайпов вверх и 5 вниз (`input swipe 360 1000 360 350 300` и обратно, пауза 1 с), `dumpsys gfxinfo`.
- Замеры чередуются: вкл, выкл, вкл, выкл… — 3 пары. Скрипт — `runs/perf.sh`, сырьё — `perf/gfx-{on,off}-{1,2,3}.txt`.
- Хост в это время был нагружен другими сборками: load average 6–8, до того до 31.

| Замер | Кадров | Janky | p50 | p90 |
| --- | --- | --- | --- | --- |
| вкл 1 | 336 | 96.4 % | 93 мс | 150 мс |
| выкл 1 | 160 | 96.3 % | 73 мс | 105 мс |
| вкл 2 | 373 | 92.0 % | 73 мс | 129 мс |
| выкл 2 | 113 | 98.2 % | 77 мс | 129 мс |
| вкл 3 | 316 | 98.7 % | 97 мс | 150 мс |
| выкл 3 | 126 | 98.4 % | 69 мс | 109 мс |
| **медиана вкл / выкл** | 336 / 126 | — | **93 / 73 (+27 %)** | **150 / 109 (+38 %)** |

По средним то же: p50 87.7 / 73.0 (+20 %), p90 143 / 114 (+25 %).

**Замечание** (критерий плана — рост больше 20 %):
- С градиентом кадров в 2–3 раза больше: после каждого свайпа слой пятен ещё 1.5–2 с рисует возврат и импульс, а без градиента приложение после скролла не рисует.
- Каждый такой кадр — три радиальных градиента на весь экран. На SwiftShader их рисует CPU хоста, поэтому медленные кадры фона тянут перцентили вверх.
- Janky ~92–99 % в обоих режимах — эмулятор не держит 60 Гц и без фичи.
- Вердикт — за замером на настоящем телефоне (`dumpsys gfxinfo` тем же скриптом). На эмуляторе это ориентир.

# Редактор: касания вне текста, ручка вставки, меню «⋯» как модалка

- **Дата:** 2026-11-11.
- **Статус:** дизайн утверждён пользователем в сессии 2026-11-11; спека прошла ревью (одна итерация правок).
- **Slug:** `editor-touch-and-format-sheet`.
- **Основа:**
  - нативный редактор `ui/editor/engine/TesseraEditText`;
  - стеклянный бар формата в `NoteEditorScreen`;
  - общий попап `core/ui/components/TesseraPopup` (его использует `SearchOptionPopup` на экране поиска).
- **Вне рамок:**
  - теги и папки — отдельная спека `2026-11-11-tag-folder-appearance-design.md`;
  - ячейки таблиц (`TableOverlayHost`) — у них своя платформенная каретка, ручка вставки там остаётся как есть.

## 1. Жалобы пользователя и их причины

| # | Жалоба | Причина (по коду) |
| --- | --- | --- |
| 1 | Долгое нажатие на пустом месте под текстом выделяет слово над ним | `TesseraEditText` занимает всю высоту под текстом. `Editor.performLongClick` переводит точку через `getLineForVertical`, которая прижимает её к последней строке. На API 29+ ветка «не по тексту» есть только при включённом контроллере вставки и только если по x палец правее конца строки; иначе (и всегда на 26–28) вызывается `selectCurrentWordAndStartDrag` — выделяется ближайшее слово |
| 2 | При фокусе под кареткой всегда появляется «капля» | Ручка вставки `InsertionHandleView`. На API 29+ `hidePlatformCaret()` ставит прозрачный `textCursorDrawable` (`NoCaret`) и оставляет `isCursorVisible = true` — ради ручки, она показывается после каждого тапа на ~4 с. На 26–28 там `isCursorVisible = false`, ручки нет уже сейчас |
| 3 | Меню «⋯» с анимацией появляется над клавиатурой | `MarkdownFormatMenu` — отдельное окно `Popup`, оно рисуется поверх окна IME |
| 4 | Меню нельзя закрыть той же кнопкой «⋯» | Тап по кнопке — «тап снаружи» окна `Popup`: `onDismissRequest` закрывает меню, затем `onToggleMenu` открывает его снова |
| 5 | Меню блокирует жест «назад» | Наблюдение пользователя на сборке с `9b83ada`. Новое поведение — §4.5, проверка на эмуляторе |

## 2. Ручка вставки («капля»)

**Поведение.**
- Ручки вставки нет вообще — ни после тапа, ни при фокусе, ни при открытии заметки, ни после набора, на API 26–36. Видна только каретка, которую рисует движок.
- Вместе с ручкой уходит платформенный пузырь «Вставить» по тапу на каретку. Вставка доступна:
  - долгим нажатием вне текста (§3);
  - в панели выделения при выделенном тексте;
  - с клавиатуры.
- Ручки выделения (левая и правая) при выделенном тексте работают как сейчас.

**Механика.**
- `hidePlatformCaret()` ставит `isCursorVisible = false` на всех API (сейчас — только ниже Q). Тогда `Editor.prepareCursorControllers` выключает контроллер вставки (`mInsertionControllerEnabled = enabled && isCursorVisible()`): окна ручки нет, и невидимой цели под кареткой тоже нет.
- Контроллер выделения от `isCursorVisible` не зависит.
- Каретку и так рисует движок (`caretShown`/`restartBlink`), на 26–28 это уже работает так.
- Прозрачный `NoCaret` больше не нужен — удаляется, если других использований нет.
- `handlesHidden` больше не трогает `isCursorVisible`: курсор и так невидим, ручки вставки нет. Свойство и его вызовы остаются, сеттер — без этой строки.
- `applyCursorAndHandleTint` в `NoteBody` не меняется.

## 3. Касания вне текста

**«Вне текста»** — точка касания `(x, y)` в координатах view, для которой (с учётом `totalPaddingTop`, `scrollY`, `totalPaddingLeft`):
- `y` ниже нижнего края последней строки layout'а, **или**
- `y` на строке, а `x` вне отрезка `[getLineLeft(line), getLineRight(line)]` этой строки — правее конца короткой строки или на пустой строке.

Точки на чекбоксе, картинке и поле таблицы («цели» `tapTarget`, `imageTapTarget`, `tableTapTarget`) обрабатываются как сейчас и в правило не входят.

**Поведение (редактируемая заметка).**

| Жест | Где | Результат |
| --- | --- | --- |
| Долгое нажатие | ниже последней строки | Каретка в **конец заметки** (§3.1). Клавиатура показывается. Плавающее меню: «Вставить» (если в буфере есть текст), «Выбрать всё» (если заметка не пустая). Ничего не выделяется |
| Долгое нажатие | на строке, но вне её текста | Каретка в ближайшую позицию этой строки (`getOffsetForPosition`, для пустой строки — её начало). Клавиатура, меню — как выше |
| Долгое нажатие | по тексту | Как сейчас: выделяется слово, панель выделения |
| Тап | ниже последней строки | Каретка в конец заметки (§3.1), клавиатура (сейчас — в точку последней строки под пальцем по x) |
| Тап | всё остальное | Как сейчас |

**Только чтение** (зритель общей заметки): долгое нажатие ниже последней строки ничего не делает — ни выделения, ни меню. Остальное как сейчас.

### 3.1 «Конец заметки»

- Последний абзац — текстовый: каретка в его конец.
- Последний абзац — объект (картинка, таблица, разделитель): как `caretNextToTable(ps объекта, above = false)` — та же функция работает для любого абзаца-объекта по `objectRect`.
- Правило «каретка не стоит перед сентинелом» соблюдается: каретку ставит `setSelection`, `onSelectionChanged` правит позицию, как сейчас.

### 3.2 Механика

- **`TesseraEditText.handleTouch`, `ACTION_DOWN`:**
  - запоминается, что жест начался «вне текста» и где (`downOutside: Outside? = BelowText | OffLine(offset)`) — по правилу выше, если нет цели;
  - вычисляется **до** проверки `ready && editable`, чтобы у зрителя тоже был известен;
  - решение держится до конца жеста;
  - сбрасывается на `ACTION_UP` и `ACTION_CANCEL` — иначе `ACTION_LONG_CLICK` от TalkBack прочитал бы прошлый жест;
  - любой `ACTION_DOWN` закрывает открытое наше меню (`finish`).
- **`override fun performLongClick(): Boolean`.** Если `downOutside != null` и редактор готов:
  - **редактируемый:** `performHapticFeedback(LONG_PRESS)` (платформенную вибрацию даёт `TextView.performLongClick`, который мы обходим), `requestFocus()`, `setSelection(offset)` (§3.1 для `BelowText`), `showSoftInput` (как в `caretNextToTable`), старт меню (ниже), `return true`;
  - **только чтение:** `return true` без действий.

  Иначе — `super.performLongClick()`. Platform `Editor.performLongClick` в нашем случае не вызывается, поэтому слово не выделяется ни на одном API.
- **`ACTION_UP` жеста, где сработало наше долгое нажатие:** в `super.onTouchEvent` уходит `ACTION_CANCEL`, возвращается `true` — как в существующих ветках картинки и чекбокса. Платформенная обработка отпускания не двигает каретку и не закрывает меню.
- **`ACTION_UP` тапа** (короче `longPressMs`) при `BelowText`:
  - `ACTION_CANCEL` в `super`;
  - `requestFocus()` + `setSelection(конец)` (§3.1) + `showSoftInput`;
  - `return true`.
- **Меню** — свой floating `ActionMode`: `startActionMode(callback, ActionMode.TYPE_FLOATING)`.
  - `callback` — `ActionMode.Callback2`, `onGetContentRect` отдаёт прямоугольник каретки.
  - Пункты:
    - `android.R.id.paste` с заголовком `android.R.string.paste` — если `ClipboardManager.hasPrimaryClip()` и в клипе есть текст;
    - `android.R.id.selectAll` с заголовком `android.R.string.selectAll` — если текст не пуст.

    Системные строки уже локализованы.
  - **Нажатие:**
    - «Вставить» → `onTextContextMenuItem(android.R.id.paste)` (через `ClipboardBridge` движка, как обычная вставка) → `mode.finish()`;
    - «Выбрать всё» → `mode.finish()`, затем `performAccessibilityAction(ACTION_SET_SELECTION, 0..length)`. Эта ветка `TextView` сама запускает платформенный режим выделения (`startSelectionActionModeAsync`): ручки и «Копировать / Вырезать» появляются. `onTextContextMenuItem(selectAll)` не годится — он подсвечивает текст без ручек и панели, потому что наш режим не принадлежит `Editor`. Если путь через accessibility на устройстве не даёт панели (тест §6.2-2b), пункт «Выбрать всё» убирается из меню. Это решение записывается в отчёт.
  - Нет ни одного пункта — меню не показывается, остаются каретка и клавиатура.
  - **Меню закрывается** при наборе (`onTextChanged`), при смене выделения (`onSelectionChanged`) и на любом `ACTION_DOWN`.
- **Инерционная прокрутка** (`63ba51b`) не затрагивается: координаты событий не меняются. Касание, остановившее прокрутку (`caughtFling`), долгим нажатием и тапом не считается, как сейчас.

## 4. Меню «⋯» как модалка

### 4.1 Вид

Как `SearchOptionPopup` (`TesseraPopup`).

- **Фон.** Под карточкой — размытый (`hazeEffect`, `GlassBlurRadius`) и затемнённый (`scrim` 25 %) фон на весь экран, включая верхний бар.
- **Карточка:**
  - форма, цвет, тон и тень — от `TesseraPopup`;
  - заголовок `headlineSmall` / SemiBold: «Стиль абзаца» / «Paragraph style» (новая строка `editor_style_menu_title` в `values` и `values-ru`);
  - строки `formatMenuEntries` — иконка 20 dp и подпись `bodyLarge`.
- **Строки** свёрстаны как в `SearchOptionPopup`: `Surface`, форма 16 dp, отступы `TesseraSpacing.md`.
  - Строка текущего вида абзаца (`formatState.paragraph == ParagraphFormat.Single(kind)`): фон `secondaryContainer`, текст и иконка `onSecondaryContainer`, вес Medium.
  - Остальные строки: фон прозрачный, текст `onSurface`, иконка `onSurfaceVariant`.
- **Бар формата** (пилюля с полями) — **чёткий**, над фоном, нажимаемый. Его стекло размывает `Scaffold`, а не затемнение модалки, поэтому пилюля светлее фона. Так и задумано: бар выделяется. Проверяется на снимках.
- Цвета — только `MaterialTheme.colorScheme.*`, отступы — `TesseraSpacing`. Light и dark.

### 4.2 Слои экрана (`NoteEditorScreen`)

Бар формата уходит из слота `bottomBar` у `Scaffold` в корневой `Box` экрана. Порядок слоёв снизу вверх:

1. **`Box(Modifier.hazeSource(hazeState))` вокруг всего `Scaffold`** (верхний бар + колонка заметки), как на главном экране (`4f5a0a4`). `hazeSource` с `Column` **снимается**. Эффект Haze внутри своего источника ничего не рисует, поэтому стеклянный бар — сосед источника, не потомок.
2. **Модалка меню** (`TesseraPopup`): фон и карточка.
3. **Бар формата.** Логика та же:
   - `AnimatedVisibility(imeVisible && !isReadOnly)` с теми же анимациями;
   - `imePadding`, поля 16/8 dp;
   - `pointerInput`, который берёт касания полей без поглощения;
   - `tesseraGlass(hazeState, …)`, `tesseraGlassShadow`;
   - `TableActionsBar` вместо `EditorFormatBar`, когда каретка в таблице;
   - `onSizeChanged` → `barExtentPx`.

   `Box` бара выравнивается `Alignment.BottomCenter`.
4. **Остальное как сейчас:** `TagPickerPopup`, `MembersSheet`, диалоги.

**Отступы колонки заметки после переноса** (Scaffold без `bottomBar` даёт снизу только навбар — он не используется):
- **сверху** — `padding.calculateTopPadding()`, как сейчас;
- **снизу** — `if (imeVisible) WindowInsets.ime.getBottom(density) else 0`, в dp;
- `NoteBody.bottomInsetPx` — `if (imeVisible && !isReadOnly) barExtentPx else 0`, как сейчас.

**Инвариант:** раскладка заметки и бара по пикселям та же, что на `master` после `9b83ada`. Без клавиатуры отступа нет: заметка прокручивается до самого края экрана, под жестовую полоску (решение пользователя 2026-11-11).

**Побочный эффект:** `TagPickerPopup` в редакторе теперь размывает и верхний бар, как попапы главного экрана.

### 4.3 `TesseraPopup`: два необязательных параметра

| Параметр | По умолчанию | Что делает при не-умолчании |
| --- | --- | --- |
| `bottomInset: Dp` | `0.dp` | Место под карточкой (в редакторе — `barExtentPx` в dp). Карточка встаёт над ним, отступ `cardBottomGap` сохраняется. Макс. высота карточки = `max(144.dp, место от низа статус-бара до верха карточки)`, но не больше 60 % экрана. Нижняя граница 144 dp (≈ три строки) — для ландшафта с клавиатурой: там пустая карточка хуже, чем заход под статус-бар. Список внутри прокручивается |
| `clearFocusOnDismiss: Boolean` | `true` | `false`: закрытие не снимает фокус, клавиатура остаётся |

- При значениях по умолчанию код пути и вид всех остальных попапов не меняются: максимальная высота — прежние 60 % экрана, без учёта статус-бара.
- Тесты `app/src/androidTest/…/TesseraPopupTest`, `…/TesseraPopupSwipeTest` и скриншоты попапов зелёные без правок.
- Свайп карточки вниз закрывает меню, как у всех попапов.

### 4.4 Состояние и закрытие

- `formatMenuExpanded` поднимается на уровень `NoteEditorScreen` (сейчас живёт внутри `AnimatedVisibility` бара).
- **Открывает и закрывает** кнопка «⋯» (`onToggleMenu`). Бар над фоном модалки, поэтому тап по «⋯» при открытом меню доходит до кнопки и закрывает меню.
- **Тоже закрывают:**
  - тап по фону;
  - свайп карточки вниз;
  - «назад» (§4.5);
  - **любая другая кнопка бара** («жирный», список и т. д.): её действие выполняется, меню закрывается. Делается обёрткой действий бара на уровне экрана, по образцу `wrapActions`;
  - **выбор строки:** стиль применяется к абзацу с кареткой, меню закрывается, фокус, каретка и клавиатура остаются.
- **Меню закрывается само, когда:**
  - клавиатура спрятана;
  - каретка ушла в таблицу (`nativeTableBar != null`);
  - заметка только для чтения.
- Клавиатура при открытом меню остаётся. Поверх клавиатуры ничего не рисуется: модалка — слой окна приложения.

### 4.5 «Назад»

| Состояние | Жест «назад» | Результат |
| --- | --- | --- |
| Меню открыто, клавиатура видна | один жест | Жест забирает IME (так устроен Android): клавиатура прячется, вместе с ней бар и меню (§4.4). Заметка остаётся открытой |
| Меню открыто, клавиатуры нет | — | Не бывает (§4.4) |
| Меню закрыто | как сейчас | Первый жест прячет клавиатуру, следующий сохраняет заметку и выходит |

`BackHandler` модалки объявлен позже `BackHandler` экрана и, пока меню открыто, перехватывает «назад», если жест дошёл до приложения. Заметка не закрывается.

  - `AboveBarPositionProvider`, `ShadowRoom*`, `FromButton`;

  - строки по `formatMenuEntries`;

- Скриншоты открытого меню в light и dark (`captureScreenRoboImage`, memory `roborazzi_screenshot_gotchas`): фон, карточка над баром, бар чёткий. Golden записывает только оркестратор, с фильтром по классу.

  - ниже последней строки;
  - правее короткой строки;
  - пустая строка;
  - по тексту → `null`.

### 6.2 Instrumented на эмуляторе (`app/src/androidTest`)

Тесты пишутся по поведению пользователя. Касания — через `adb shell input` / `UiAutomation`: тестовое правило Compose искажает тап и долгое нажатие (memory `compose-test-rule-gesture-artifact`, `device-e2e-gotchas`).

1. **Ручки вставки нет.**
   - Тап по тексту, тап под текстом, открытие заметки: PixelCopy окна в квадрате 48×48 dp под кареткой совпадает с тем же квадратом до тапа. Каретку исключить: снимок в фазе мигания «выкл» или маска её прямоугольника.
   - Тап сразу под кареткой (в 20 dp ниже) **двигает каретку** туда, а не открывает меню.
   - На образе API 29+ обязательно, на 26–28 — если образ есть на машине; иначе отметить в отчёте.
2. **Долгое нажатие под текстом** (в буфер заранее кладётся текст):
   - выделение пустое;
   - каретка в конце заметки;
   - клавиатура видна;
   - в окнах `UiAutomator` есть пункт «Вставить» / «Paste»;
   - нажатие на него вставляет текст буфера в конец;
   - **2b.** Повтор долгого нажатия → «Выбрать всё»: выделен весь текст, видны ручки выделения и пункт «Копировать» / «Copy».
   - Долгое нажатие даёт вибрацию: `HapticFeedbackConstants.LONG_PRESS` вызван — через тестовый спай или лог.
3. **Долгое нажатие правее короткой строки:** выделение пустое, каретка в конце этой строки, меню есть.
4. **Долгое нажатие по слову** (в том числе последней строки) выделяет слово, как раньше.
5. **Тап под текстом** ставит каретку в конец заметки. Если заметка кончается таблицей — как `caretNextToTable(…, above = false)`.
6. **Зритель общей заметки:** долгое нажатие под текстом не выделяет и не показывает меню.
7. **«⋯»:**
   - открывает меню, повторный «⋯» закрывает;
   - тап по фону закрывает;
   - «жирный» при открытом меню делает жирным и закрывает меню;
   - выбор «Заголовок» делает абзац заголовком, меню закрыто, клавиатура видна, каретка на месте.
8. **Геометрия и «назад»:**
   - карточка целиком выше бара, бар целиком выше клавиатуры;
   - «назад» при открытом меню — заметка не закрылась, меню закрыто;
   - следующий «назад» ведёт себя как без меню.

## 7. Риски

- **Перенос бара из `Scaffold`** может сдвинуть колонку на высоту навбара или IME. Ловят формула §4.2 и тесты §6.2-8/9.
- **`isCursorVisible = false` на 29+** выключает и платформенный пузырь «Вставить» по тапу на каретку — это принятое следствие §2. Если на каком-то API пропадёт и панель выделения, это ловит §6.2-4.
- **Свой `ActionMode` вместо платформенного** — меню держит только «Вставить» и «Выбрать всё». Пункты платформы (автозаполнение, «Перевести») здесь не появятся. Для пустого места это не нужно.

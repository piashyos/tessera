- **Дата:** 2026-06-23
- **Область:** ручная приёмка шаринга заметок на двух реальных устройствах/аккаунтах
- **План фазы:** [2026-06-23-shared-notes-phase5-integration](../plans/2026-06-23-shared-notes-phase5-integration.md)
- **Спеки:** [Доступ и UI](2026-06-23-shared-notes-access-design.md)

## Предусловие

> **ОБЯЗАТЕЛЬНО:** обновлённые `firestore.rules` задеплоены в Firebase-проект:
> ```
> firebase deploy --only firestore:rules
> ```
> Без актуальных правил любой шаринг будет отклонён на сервере (`PERMISSION_DENIED`), и UI покажет ошибку.

- Два устройства (или эмулятор + устройство), два разных Google-аккаунта:
  - **A** — владелец заметки.
  - **B** — приглашённый участник.
- Оба аккаунта хотя бы раз вошли в приложение (чтобы попасть в индекс `usersByEmail` — иначе инвайт по email вернёт «Пользователь не найден»).

## Сценарий жизненного цикла

| # | Шаг | Ожидаемый результат | ✅ |
|---|-----|---------------------|----|
| 1 | **A:** создать заметку → ⋮ → «Сделать общей» | Открывается лист участников (`MembersSheet`). Если бэкенд вернул ошибку — показывается диалог с причиной (не молчаливый провал, *Fix c*). | ☐ |
| 2 | **A:** в листе пригласить **B** по email с ролью **Editor** | Состояние «Added», B появляется в ростере. Несуществующий email → inline «Пользователь не найден». | ☐ |
| 3 | **B:** дождаться синка | Заметка появляется в системной секции «Общие». На карточке — стек аватаров A + B. | ☐ |
| 4 | **B (Editor):** изменить текст заметки | После синка правка видна у **A**. | ☐ |
| 5 | **A:** сменить роль B на **Viewer** | У B редактор становится read-only (формат-бар скрыт, ввод заблокирован). Локальная правка B, сделанная до синка, **откатывается** после синка (*Fix a*). | ☐ |
| 6 | **A:** исключить B (Remove) | Заметка исчезает у B. Затем: **A** повторно приглашает B → **B** жмёт «Выйти» → заметка исчезает у B, у A остаётся. | ☐ |
| 7 | **A (Owner/Manager):** «Удалить для всех» | Заметка удаляется у всех участников. **B (Editor)** НЕ видит пункт «Удалить для всех» в ⋮ И НЕ может удалить общую заметку из списка (свайп / лист long-press) — проверить оба пути (*security gate*). | ☐ |
| 8 | **A:** «Сделать приватной» (unshare) | Заметка возвращается в приватный список A, у B исчезает. | ☐ |

## Регресс и новые точки входа (фиксы этой фазы)

| # | Шаг | Ожидаемый результат | ✅ |
|---|-----|---------------------|----|
| 9 | **A:** открыть заметку со старым `ownerId=null` (создана до входа в аккаунт) → ⋮ | Пункт «Сделать общей» **доступен** (раньше был скрыт). При шаринге `ownerId` присваивается текущему пользователю (*Bug 1*). | ☐ |
| 10 | **A:** в списке заметок long-press по **приватной** заметке | В нижнем листе доступно «Сделать общей» (*Feature 3*). Для уже **общей** заметки или при роли Viewer/Editor — пункт скрыт; удаление общей заметки из списка недоступно не-менеджеру (*delete gate*). | ☐ |

  `NoteEditorViewModelTest`, `NotesListViewModelTest`, `sharede2e.*` (`InMemorySharedBackendTest`,
  `SharedNotesTestDeviceTest`, `TwoUserSharedNotesE2ETest`), `NoteMapperTest` — **97 тестов, все зелёные**.
- Node rules-харнесс: `cd firestore-rules-tests && npm test` — **26/26 зелёные** (включая `flow.test.js`, запускается сериализованно через `--test-concurrency=1`).
- **Флейки скриншот-тестов:** полный `testDebugUnitTest` падает с `UnsatisfiedLinkError: RenderNodeNatives.nCreate` при параллельном запуске Roborazzi-тестов. Это проблема среды/конкуренции нативного рендера, **не регресс**: один скриншот-тест в изоляции проходит — проверено
  `./gradlew :app:testDebugUnitTest --tests "*MembersSheetScreenshotTest"` → BUILD SUCCESSFUL.
  Поэтому в приёмочном гейте JVM-логика и скриншоты гоняются раздельно.

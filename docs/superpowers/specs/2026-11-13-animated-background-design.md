# Живой фон: градиент, который двигается от касаний, и размер зерна

Дата: 2026-11-13. Дизайн утверждён пользователем в чате; дальше пользователь просил вести без него.

## 1. Что хотим

- На фоне приложения — едва заметный градиент из 3 цветов текущей палитры. Он виден всегда, пока включён в настройках.
- Любое касание экрана (тап, скролл, свайп, перетаскивание) плавно и ненавязчиво сдвигает градиент «волной» по
  направлению жеста; через 1.5–2 с он успокаивается. Печать в редакторе фон не трогает.
- В настройках — переключатель градиента и ползунок размера зерна.

Решения пользователя (2026-11-13, дословно по вопросам):
- Цвета — «Из палитры темы».
- Движение — «Волна по жесту»: в покое фон стоит, жест даёт импульс по направлению, затухание 1.5–2 с.
- По умолчанию — «Включён».

## 2. Где сейчас

- `core/ui/theme/GrainOverlay.kt` — корневой фон приложения: `drawBehind { drawRect(background); drawRect(grainBrush, alpha) }`,
  плитка шума 160×160 px, 1 px на зерно, фиксированный seed. Экраны прозрачные, фон виден между карточками.
- `MainActivity` читает `grainEnabled` / `grainIntensity` из `UserPreferences` (`produceState` + `cached*`) и оборачивает
  `TesseraApp()` в `GrainOverlay` внутри `TesseraTheme`.
- Настройки: `SettingsScreen.AppearanceSection` — строки «Тема», «Язык», «Зернистость» (Switch) и, если включено,
  `GrainIntensityRow` (Slider 0..1, сохраняет на `onValueChangeFinished`).
- Данные: `UserPreferences` (интерфейс) / `UserPreferencesRepository` (DataStore, ключи `grain_enabled`, `grain_intensity`,
  кэш `lastX` для синхронного чтения), `test/fakes/FakeUserPreferences`.

## 3. Как выглядит

Слои снизу вверх: цвет `background` → 3 пятна градиента → зерно → контент. Зерно остаётся поверх пятен, чтобы
градиент не гасил его.

| Пятно | Цвет | Центр в покое (доли ширины, высоты) | Радиус (доля ширины) |
| --- | --- | --- | --- |
| A | `primaryContainer` | (0.15, 0.12) | 0.80 |
| B | `tertiaryContainer` | (0.90, 0.48) | 0.70 |
| C | `secondaryContainer` | (0.30, 0.92) | 0.85 |

- Пятно — `Brush.radialGradient(color.copy(alpha = a) → color.copy(alpha = 0f))`. Пиковая альфа `a`: светлая тема 0.35, тёмная 0.25
  (константы `BackdropAlphaLight` / `BackdropAlphaDark`). Тема определяется по `background.luminance() < 0.5`.
  Критерий «едва заметно»: на скрине фон узнаётся как цветной только при сравнении с выключенным градиентом. Если
  на устройстве цвет читается сразу или не читается совсем, альфы подстраиваются (это константы, не логика) и
  итог записывается в план.
- Отрисовка — дети корневого `Box` по порядку:
  1. корень: `drawBehind { drawRect(background) }` — только цвет;
  2. слой пятен (если градиент включён): `Box(Modifier.fillMaxSize().graphicsLayer().drawWithCache { … })` — кисти
     строятся один раз в позиции покоя (пересборка — при смене размера или цветов), на кадр анимации — только
     `translate` / `scale` вокруг центра пятна; движение перерисовывает только этот слой;
  3. слой зерна (если зерно включено): `Box(Modifier.fillMaxSize().graphicsLayer().drawBehind { зерно })` —
     статичный, свой слой, при движении пятен не перерисовывается;
  4. контент.
  Слои 2 и 3 — только рисование, без `pointerInput` и без semantics: соседям они попадания не перекрывают.
- В режиме AMOLED при тёмной теме (`amoled && resolvedDark`, то есть настоящий чёрный) градиент не рисуется.
- Как и зерно, градиент виден только там, где экран прозрачный: карточки, панели, шторки его перекрывают.
  Под стеклом (haze) его тоже нет: haze рисует свой `backgroundColor` и размывает только содержимое экрана.

## 4. Движение «волной по жесту»

### 4.1 Источник событий

- В корневом `Box` фона — `Modifier.pointerInput` с `awaitPointerEvent(PointerEventPass.Initial)` в цикле. Он только
  читает события и НИКОГДА не вызывает `consume()`: жесты экранов (скролл, свайп карточек, попапы, `AndroidView` редактора)
  работают как раньше. Слушатель стоит, только пока градиент включён.
- Слушатель — на `Box`-предке всего контента, НЕ на слое пятен: read-only `pointerInput` на соседнем узле забирает
  попадание у соседей ниже (memory `compose_consumed_down_blocks_child_scroll`).
- Учитываются только указатели с `pressed && previousPressed`. Смещение кадра — среднее `position - previousPosition`
  по ним.
- Жест, отменённый системой (`ACTION_CANCEL`: back-свайп от края, перехват касания другим окном), — пятна
  возвращаются в покой (импульс нажатия к этому моменту уже сыгран — §4.2). Признак отмены на корне в проходе
  `Initial` (поведение ui 1.11.3: `onCancelPointerInput` синтезирует отпускание, сразу помеченное consumed, а обычный
  `up` в `Initial` ещё никем не поглощён): `change.changedToUpIgnoreConsumed() && change.isConsumed`. Покрыто тестом (§8).
- Первое нажатие жеста (`changedToDown`, когда до этого ни один указатель не был прижат) — «импульс» от точки
  касания (§4.2). Так видна реакция на любой тап, в том числе по заметке, когда экран сразу сменяется: фон —
  корневой и общий для всех экранов, импульс доигрывает за новым экраном.
- Ввод с клавиатуры — не указатель, поэтому печать фон не трогает. Тап в текст (курсор), скролл текста, кнопки панели
  формата — касания, они фон двигают.
- `AlertDialog` / `ModalBottomSheet` / меню, а также ручки выделения и панель действий с текстом у `EditText` живут
  в отдельных окнах и не видны слушателю — на них фон не реагирует (принято). `TesseraPopup` живёт в окне
  приложения — реагирует.

### 4.2 Модель (чистая, `core/ui/theme/BackdropMotion.kt`)

- `limitPx = 0.09 × min(ширина, высота)` — предел сдвига пятна.
- `nudge(current: Offset, delta: Offset, gain: Float, limitPx: Float): Offset` — `current + delta × gain`, ограниченный
  кругом радиуса `limitPx` (по длине вектора, направление сохраняется). `current` — накопленная цель пятна: синхронный
  `var target: Offset` в `BackdropMotionState`, по одному на пятно (как аккумулятор в `TesseraPopup`), не `animatable.value` (отстаёт из-за
  пружины) и не `targetValue` (обновляется асинхронно, после захвата `MutatorMutex`). Обнуляется в `onRelease` /
  `onCancel`. Длинный жест доходит до предела.
- Коэффициенты пятен `gain` = A 0.35, B 0.25, C 0.15 — разная сила даёт разлёт пятен, то есть «волну».
- Каждое пятно — свой `Animatable<Offset>`:
  - на кадр движения: `target = nudge(target, delta, gain, limitPx)`, затем
    `animateTo(target, spring(dampingRatio = 1f, stiffness = Low, visibilityThreshold = Offset.VisibilityThreshold))`;
  - когда все указатели отпущены: `animateTo(Offset.Zero, spring(dampingRatio = 0.6f, stiffness = k,
    visibilityThreshold = Offset.VisibilityThreshold))` — лёгкий перелёт и успокоение; жёсткость A 25, B 32, C 40 —
    пятна возвращаются вразнобой, это и есть волна. `visibilityThreshold` обязателен: без него порог Compose 0.01 px
    и анимация тянется ~3 с вместо ~1.8 с.
    Расчёт: при ζ = 0.6 и k = 25 затухание ζ√k = 3 с⁻¹, от предела ~100 px до 0.5 px — около 1.8 с; C — около 1.4 с.
    Цель — 1.5–2 с на глаз; константы подстраиваются на устройстве (как альфы в §3), итог — в план.
- «Импульс» на нажатие (заменяет прежний «вдох» на тап — пользователь 2026-11-13: «но почему при кликах на заметки
  фон никак не реагирует, он должен реагировать на все»; «вдох» ×1.08 только на отпускании без сдвига был почти
  незаметен, а при тапе по заметке доигрывал за сменой экрана):
  - одна общая `Animatable` `pulse` 0 → 1 → 0: подъём `spring(dampingRatio = 1f, stiffness = MediumLow)`, спад
    `spring(dampingRatio = 0.6f, stiffness = 40f)` — около 1.5 с всего;
  - точка `pulseOrigin` — позиция нажатия (snapshot-состояние, пишется при нажатии);
  - на отрисовке каждое пятно дополнительно сдвинуто ОТ точки нажатия: `dir_i × pulse × PulseAmplitude_i × limitPx`,
    где `dir_i` — единичный вектор от `pulseOrigin` к центру пятна в покое (нулевая длина — без сдвига),
    `PulseAmplitude` = A 0.6, B 0.45, C 0.3 — пятна разлетаются вразнобой, волной от пальца;
  - масштаб радиусов `1 + (PulseScale − 1) × pulse`, `PulseScale = 1.15`;
  - новое нажатие во время импульса перезапускает его от текущего значения (без скачка);
  - импульс независим от смещений жеста (`offset(i)`): перетаскивание и возврат идут как раньше, сумма — на отрисовке;
  - при «Удалить анимации» импульс не играет (та же защита).
  Амплитуды и масштаб — константы, подбираются на устройстве «заметно, но мягко»; итог — в план.
- Подбор на устройстве (2026-11-13, emulator-5556, замеры `BackgroundGradientTest`, максимальный сдвиг цвета пикселя):
  - исходные числа (предел 0.09, амплитуды 0.6 / 0.45 / 0.3, ×1.15) — 2–4 уровня из 255: глазом не видно;
  - вариант qa A (предел `BackdropLimitFraction` 0.2, амплитуды 1.0 / 0.8 / 0.6, `PulseScale` 1.3, спад импульса —
    жёсткость 20) — 4–5 уровней: тинт в покое отличается от фона всего на 10–12 уровней, сдвиг таких пятен не может
    изменить картинку сильнее;
  - поэтому импульс ещё и «светит»: кисти строятся с альфой `blobAlpha × PulseGlow` (`PulseGlow` = 2), рисуются с
    альфой `pulseGlowAlpha(pulse)` = (1 + (PulseGlow − 1) × pulse) / PulseGlow — в покое ровно прежний тинт (golden в
    покое не изменились), на пике импульса — вдвое насыщеннее, гаснет вместе с импульсом.
- В покое анимаций нет — кадры не рисуются. Значения читаются в draw-лямбде слоя пятен, поэтому движение — только
  перерисовка этого слоя, без рекомпозиции.
- Системное «Удалить анимации»: при `durationScale == 0` любая `animateTo` за один кадр прыгает к цели, то есть пятна
  скакали бы. Защита обязательна: перед запуском анимаций `BackdropMotionState` читает
  `scope.coroutineContext[MotionDurationScale]?.scaleFactor ?: 1f`, где `scope` — `rememberCoroutineScope()` внутри
  `rememberBackdropMotionState` (Compose кладёт туда `MotionDurationScale` и обновляет его из системной настройки;
  отсутствие элемента считается за 1). При 0 ничего не запускается — пятна стоят в покое. Чтение — в момент жеста,
  чтобы смена настройки при открытом приложении учитывалась. Ветка покрыта тестом (§8).

### 4.3 Состояние

`BackdropMotionState` (`rememberBackdropMotionState()`): три `Animatable<Offset>` и `Animatable` импульса,
`onPress(position)`, `onDrag(delta, size)`, `onRelease()`, `onCancel()`; чтение `offset(i)`, `pulse`, `pulseOrigin` и
`scale` (= `1 + (PulseScale − 1) × pulse`). `onTap()` и определение тапа по `touchSlop` убраны — реакция на нажатие
у всех жестов одинаковая. `GrainOverlay` принимает состояние необязательным параметром — тесты передают свой.

## 5. Размер зерна

- `grainSize: Int` 1..4, по умолчанию 1 (как сейчас).
- Плитка: сетка шума 160 × 160 ячеек при любом `s`, каждая ячейка — квадрат `s × s` px одного цвета; сторона
  плитки `160 × s` (640 px при ×4). Число уникальных ячеек не падает с размером — иначе при ×4 плитка в 40 × 40
  ячеек повторяется каждые 160 px и читается как узор «обоев» (так было в первой версии, поймано на скриншоте).
  Тот же seed — узор стабилен. Пересборка — `remember(showGrain, grainSize)`.
- Функция `grainTile(grainSize: Int): GrainTile` (`class GrainTile(val side: Int, val pixels: IntArray)`, без `data`:
  массив сравнивается через `contentEquals`) — чистая, с тестом. При `grainSize = 1` результат побитно совпадает с
  нынешней плиткой (160 × 160, `Random(0)`, тот же порядок чтения): у кого размер по умолчанию, тот не увидит
  изменений.

## 6. Настройки

`AppearanceSection`, порядок: Тема · Язык · **Градиент фона** · Зернистость · (если зерно включено) Интенсивность ·
**Размер зерна**.

- «Градиент фона» — `SettingsRow` с `Icons.Rounded.Gradient`, подзаголовок, `Switch`; клик по строке переключает.
- «Размер зерна» показывается, как и «Интенсивность», только при включённом зерне. Это та же приватная
  `GrainIntensityRow`, расширенная параметрами (подпись, `valueRange`, `steps`) — не копия: подпись `bodySmall`,
  `Slider(valueRange = 1f..4f, steps = 2)`, локальное значение при перетаскивании, сохранение на
  `onValueChangeFinished` (`roundToInt()`).
- Цепочка до экрана: `SettingsScreen` получает колбэки `onSetGradientEnabled`, `onSetGrainSize` и значения
  `gradientEnabled`, `grainSize` (из `SettingsState`), передаёт в `AppearanceSection`; подключение к
  `viewModel::setGradientEnabled` / `viewModel::setGrainSize` — в `ui/navigation/NotesNavGraph.kt` рядом с
  `onSetGrainEnabled`.
- Строк в макете `settings-*.html` нет (как и зерна) — состояние «без макета», скрин пользователю.

## 8. Проверки

Unit (Robolectric / JUnit):
- `BackdropMotionTest`: направление сдвига совпадает с жестом; длина не больше `limitPx`; нулевой жест — без сдвига;
  повторные `nudge` с одним `delta` монотонно растут и упираются в `limitPx`.
- `GrainTileTest`: при `s` = 1..4 каждый квадрат `s × s` однороден, сторона кратна `s`, результат детерминирован;
  `s = 1` побитно равен нынешней плитке.
- `GrainOverlayGestureTest` (Robolectric):
  - внутри фона `LazyColumn` скроллится свайпом, кликабельный элемент получает клик (слушатель ничего не крадёт);
  - движение: `mainClock.autoAdvance = false`; `down` и несколько `moveBy` вниз без `up`; `advanceTimeBy(200)` —
    смещение пятна A ненулевое и направлено вниз (`y > 0`); `up`; `advanceTimeBy(3000)` — все смещения ≈ 0;
  - с выключенным градиентом смещения не меняются;
  - отмена: `down` → `moveBy` (сдвиг) → `cancel()` — после `advanceTimeBy(3000)` смещения ≈ 0 и `pulse` = 0;
  - импульс: `down` в точке левее-выше центра пятна A без `up` → через `advanceTimeBy(150)` `pulse > 0`, `scale > 1`,
    и вектор «точка нажатия → центр A» сонаправлен с дополнительным сдвигом A (скалярное произведение > 0); после `up`
    и `advanceTimeBy(2500)` — `pulse` = 0, `scale` = 1, смещения ≈ 0;
  - импульс на каждое первое нажатие: два тапа подряд — `pulse` поднимается оба раза.
- `GrainOverlayReducedMotionTest` (отдельный класс, `@OptIn(ExperimentalTestApi::class)`):
  `createComposeRule(effectContext = object : MotionDurationScale { override val scaleFactor = 0f })`; после жеста
  смещения и масштаб в покое во все моменты.
- `UserPreferencesRepositoryTest`: умолчания, запись/чтение, ограничение `grain_size`.
- `SettingsViewModelTest`: новые поля в состоянии, сеттеры доходят до репозитория.
- Roborazzi: фон в покое с градиентом, light и dark (`GrainOverlay` на весь экран с парой карточек); экран настроек
  с новыми строками (golden настроек перезапишет оркестратор).

On-device (`androidTest`, emulator-5556):
- скролл списка, свайп карточки, свайп `TesseraPopup`, тап по заметке работают как раньше (существующие наборы
  `ui.notes`, `ui.components`, `ui.editor.screen`);
- условие для проверок движения: на emulator-5556 `settings get global animator_duration_scale` ≠ 0 (проверить
  и записать в отчёт; если 0 — поставить 1 на время теста и вернуть);
- фикстура: пустое состояние списка или короткий список, который не скроллится, — область сравнения точно пустая и
  не уезжает;
- существующие пиксельные тесты: `AppearanceAppTest.theme()` (и похожие) выключает зерно — пусть так же выключает
  градиент (параметр по образцу `grain`), а кадры для сравнения снимаются после успокоения;
- перетаскивание по такой области меняет её пиксели, через 2.5 с они возвращаются к кадру покоя;
- печать в редакторе (настоящие клавиши) не меняет пиксели пустой области фона;
- плавность: `dumpsys gfxinfo` при скролле списка, отдельным процессом инструментации (memory `device-e2e-gotchas`) —
  доля janky-кадров с градиентом не хуже, чем без, больше чем на 2 п.п.;
- light / dark, AMOLED (градиента нет), выключенный градиент, размер зерна 1 и 4 — скрины.

## 9. Вне объёма

Свой выбор цветов, сила градиента, постоянный дрейф, реакция на клавиатуру, градиент под стеклом haze.
